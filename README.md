# 둘 사이

두 개의 등록 계정과 임시 게스트 입장을 지원하는 웹 메신저입니다. 메시지 기록, 현재 연결 상태, 입장·퇴장 이력을 저장합니다.

현재는 게스트 입장이 기본으로 켜져 있습니다. 로그인 화면의 **게스트로 입장**을 누르면 이름·비밀번호 입력 없이 자동 이름으로 참여합니다. 주소를 아는 누구나 같은 방의 이전 메시지와 접속 기록을 볼 수 있으며, 게스트 허용 중에는 두 사람으로 인원을 제한하지 않습니다. 등록 계정으로만 사용하려면 서버 환경변수 `ALLOW_GUESTS=false`를 설정하고 재시작하세요.

## 시작하기

Node.js 24 이상이 필요합니다.

```powershell
npm install
npm start
```

게스트 모드는 계정 등록 없이 실행할 수 있습니다. 비밀번호 로그인도 사용하려면 `npm run setup`으로 두 계정을 추가한 뒤 서버를 시작하세요.

PowerShell에서 `npm.ps1` 실행 정책 오류가 나면 `npm` 대신 `npm.cmd`를 사용하세요.

setup에서 두 사람의 이름과 서로 다른 비밀번호(12~128자)를 입력하세요. 비밀번호는 화면에 표시되지 않으며 솔트와 scrypt 해시만 저장됩니다. 기존 계정이 있으면 setup은 덮어쓰지 않습니다. `http://localhost:3000`에서 로그인하세요. 두 사람을 한 PC에서 시험하려면 일반 창과 시크릿 창을 각각 이용하세요. 같은 브라우저의 탭들은 로그인 쿠키를 공유합니다.

## 동작

- 등록 계정과 게스트가 하나의 대화방을 사용합니다. 게스트 이름과 메시지 작성자는 서버가 지정합니다. 같은 브라우저의 새로고침·추가 탭에서는 세션이 유지되며, 로그아웃·세션 만료·서버 재시작 후 다시 게스트로 입장하면 새 이름을 받습니다. 게스트 이름은 실제 신원 확인 수단이 아닙니다.
- SQLite `data/chat.sqlite`에 메시지와 접속 기록이 저장됩니다. 서버 재시작 후에도 유지되며 이전 기록은 50개씩 불러옵니다.
- 접속 중은 **로그인한 채팅 화면과 서버가 연결된 상태**입니다. 사용자가 실제로 화면을 보고 있다는 뜻이나 읽음 표시가 아닙니다.
- 같은 계정의 탭·기기 중 하나라도 연결되어 있으면 접속 중입니다. 마지막 연결이 종료되면 퇴장으로 기록됩니다. 네트워크 장애는 연결 끊김 감지까지 수십 초 지연될 수 있습니다.
- 서버 강제 종료로 정확한 퇴장 시간을 알 수 없으면 `종료 시각 미확인`으로 표시합니다.
- 시간은 서버가 UTC로 기록하고 브라우저의 현지 시간대로 표시합니다. 모든 참여자가 접속 이력을 볼 수 있습니다.
- 세션은 최대 7일이며 로그아웃 또는 서버 재시작 시 만료됩니다. 로그아웃은 같은 세션을 사용하는 모든 탭의 연결도 종료합니다.
- 최대 4,000자, 10초당 20개 메시지로 제한합니다. 전송 확인을 받지 못하면 입력을 유지하고, 같은 메시지를 재시도할 때 중복 저장을 막습니다.

## 배포와 데이터

인터넷에서 사용하려면 HTTPS를 제공하는 서버/리버스 프록시와 지속 저장 디스크가 필요합니다. 배포 환경에서 `NODE_ENV=production`, `PUBLIC_ORIGIN=https://실제도메인`을 지정하세요. `PORT`는 기본 3000, `CHAT_DB`는 데이터베이스 파일 경로를 바꾸는 옵션입니다. 프록시 뒤의 로그인 실패 제한은 기본적으로 프록시 IP 단위로 적용됩니다.

인증은 HTTP API와 Socket.IO 연결 양쪽에 적용됩니다. 메시지는 종단간 암호화되지 않으며 서버/DB 관리자에게는 보일 수 있습니다. `data` 디렉터리는 공개 정적 경로 밖에 있고 Git에서 제외됩니다. 백업은 서버를 정상 종료한 뒤 `data` 디렉터리 전체를 복사하세요. 현재 구조는 서버 프로세스 1개로 운영하는 소규모 용도입니다.

사진 업로드, 음성·영상 통화, 영상 포털은 이번 구현에 포함되지 않습니다.

## 기존 Render 서비스 업데이트

**무료 Render에서 우선 테스트하기:** Build Command `npm ci --omit=dev`, Start Command `npm start`, 환경변수 `NODE_VERSION=24.18.0`, `NODE_ENV=production`으로 실행합니다. 게스트 모드에서는 계정 환경변수를 생략해도 됩니다. `CHAT_DB`도 생략하세요. `ALLOW_GUESTS=false`가 이미 설정되어 있다면 삭제하거나 `true`로 변경해야 버튼이 표시됩니다. 무료 서비스의 재시작·절전·재배포 시 메시지와 접속 기록은 사라질 수 있습니다. 아래 Persistent Disk 설정은 기록 보존을 위해 유료 전환할 때의 안내입니다.

현재 SQLite 버전으로 기록을 보존하려면 **유료 웹 서비스 + Persistent Disk**가 필요합니다. Render의 기본 파일 시스템은 임시 저장소입니다. 무료 웹 서비스는 Persistent Disk를 지원하지 않으므로, 무료 운영을 유지하려면 외부 데이터베이스 방식으로 변경해야 합니다. [Render 디스크 안내](https://render.com/docs/disks), [무료 서비스 제한](https://render.com/docs/free)

기존 서비스의 Git 저장소와 브랜치는 유지하고 다음 설정을 먼저 적용하세요. 자동 배포가 켜져 있으면 코드 push가 배포를 시작할 수 있습니다.

1. Persistent Disk를 `/var/data` 경로에 연결합니다. 디스크 추가는 유료 설정입니다.
2. Environment에 아래 값을 등록합니다. 비밀번호는 Render 대시보드에서 직접 입력하고 Git에 넣지 마세요.

| 환경 변수 | 값 |
| --- | --- |
| `NODE_ENV` | `production` |
| `NODE_VERSION` | `24.18.0` (기존 설정이 있으면 업데이트) |
| `CHAT_DB` | `/var/data/chat.sqlite` |
| `CHAT_USER1_NAME` | 첫 번째 사용자 이름 |
| `CHAT_USER1_PASSWORD` | 첫 번째 비밀번호, 12~128자 |
| `CHAT_USER2_NAME` | 두 번째 사용자 이름, 첫 번째와 다르게 |
| `CHAT_USER2_PASSWORD` | 두 번째 비밀번호, 첫 번째와 다르게 |
| `PUBLIC_ORIGIN` | 커스텀 도메인 사용 시 `https://도메인` (끝 `/` 제외) |

기본 `onrender.com` 주소는 Render의 `RENDER_EXTERNAL_URL`을 자동 사용합니다. 계정 환경 변수는 비어 있는 DB의 첫 실행에서만 적용됩니다. 기존 계정과 대화를 덮어쓰지 않습니다. 정상 초기화 후에는 네 계정 환경 변수를 삭제해도 됩니다. 환경 변수 변경만으로 기존 비밀번호가 변경되지는 않습니다.

3. Build Command: `npm ci --omit=dev`, Start Command: `npm start`, Health Check Path: `/healthz`로 설정합니다.
4. 준비된 변경을 연결된 Git 브랜치에 push한 뒤 자동 배포 또는 **Manual Deploy → Deploy latest commit**을 실행합니다.
5. 서로 다른 브라우저로 두 계정 로그인, 메시지 교환, 로그아웃에 따른 접속 상태 변경을 확인합니다. 이후 재배포해도 기존 메시지가 남는지 확인합니다.

이전 버전은 메시지를 저장하지 않았으므로 이전 사이트에서 주고받은 대화는 가져올 수 없습니다. 배포 시 연결된 채팅은 끊기며, 새 버전에서는 계정 로그인이 필요합니다.

## 검증

`npm test`로 인증, 기록 저장, 실시간 메시지, 다중 탭 접속 상태, 로그아웃, 서버 재시작을 검증합니다.

Windows에 Edge가 설치되어 있으면 `node scripts/check-ui.js`로 데스크톱·모바일 화면의 로그인, 메시지 전달, 새로고침 복원, 로그아웃을 헤드리스 브라우저로 검사할 수 있습니다. 임시 DB와 임시 브라우저 프로필을 사용합니다.

저장소 구현은 [Node.js SQLite 공식 API](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)를 사용합니다.
